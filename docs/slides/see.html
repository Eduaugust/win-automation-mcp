02 · Two ways to see

Pixels or the element tree

Vision

screenshot → mouse_click(x, y)

  • Works on anything that renders
  • Breaks when layout, theme or scaling changes
  • Every step costs an image

UI Automation tree

find_elements → click_element

  • Reads names, roles and states, like a screen reader
  • Survives resizes and themes
  • Blind to custom-drawn UI and games

The server offers both. Try the tree first, fall back to pixels.

LLM Computer Use

09

7:00 to 7:45. Most people picture computer use as the model looking at screenshots and clicking coordinates. That works on anything, but it is fragile: a theme change, a different DPI, or a window moved by a few pixels and the click lands somewhere else. And each step means sending an image to the model. The alternative is the UI Automation tree, the same API screen readers use: every button has a name, a role and a state, so the model can say click the button named Save. That survives layout changes and is cheaper. Its weak spot is custom-drawn UI, canvases and games, where there is no tree. This server offers both, and the best results come from tree first, pixels as a fallback.
