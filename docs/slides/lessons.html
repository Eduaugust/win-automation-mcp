05 · Lessons learned

What building it taught me

Tree first, pixels second

Element names survive redesigns. Coordinates do not.

Always verify

wait_for and assert_state turn “I clicked” into “it worked”.

Expect flakiness

Slow windows, stolen focus, surprise popups. Waits beat sleeps.

Let it see its mistakes

Errors show up on screen, so the model can notice them and retry.

21:45 to 22:45. Four lessons. One: prefer the element tree; coordinates break the moment a window moves or the theme changes. Two: always verify; a tool call that returns OK only means the click was sent. wait_for and assert_state check the result. Three: the desktop is flaky by nature. Windows open slowly, other apps steal focus, update prompts pop up. Waiting for a condition beats sleeping for a fixed time. Four: because the model looks at the screen, it can see its own errors (a dialog it did not expect, a field that did not fill) and try again. A real failure from preparing this talk: the chess recording died silently at move 28. set_recording_caption rewrote the caption file in place while ffmpeg was reading it, ffmpeg hit an I/O error and stopped, and nothing reported it. That is why the end of the chess clip is marked REPLAY. The fix is a write to a temp file plus an atomic rename, and recording_status should surface a dead ffmpeg.
